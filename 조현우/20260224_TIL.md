    ### **1. 원자적 작업 분할 (Atomic Task)**
    
    에이전트에게 한 번에 너무 큰 목표를 주지 마세요. 거대한 기능은 할루시네이션(환각)의 원인이 됩니다.
    
    - **핵심 전략:** 기능을 최소 단위로 쪼개어 연쇄적으로 요청하세요.
    - **예시:** "쇼핑몰 만들어줘" (X) → "1. 상품 목록 DB 설계해줘" → "2. 목록을 보여주는 화면을 짜줘" → "3. 결제 버튼 클릭 시 결제창을 띄워줘" (O)
    - **이점:** 문제가 생겼을 때 어느 단계에서 틀렸는지 바로 찾아낼 수 있습니다.
    
    ### **2. 고밀도 컨텍스트 주입 (Context Augmentation)**
    
    에이전트가 '추측'하게 하지 마세요. 정확한 정보를 주면 버그는 사라집니다.
    
    - **핵심 전략:** 외부 API 문서, 참고 웹사이트 URL을 적극적으로 연결하세요.
    - **실천 방법:**
        - 카카오 로그인 구현 시: "카카오 개발자 문서를 참고해서 최신 방식으로 연동해줘."
        - 환경 정보 고정: "우리는 Django 5.0과 SQLite를 쓰고 있다는 걸 항상 기억해."
    
    ### **3. 결과 중심 검증: "말보다 증거(Evidence)"**
    
    비개발자 설계자에게 가장 중요한 무기입니다. 코드를 믿지 말고 **테스트 결과**를 믿으세요.
    
    - **핵심 전략:** 모든 작업 지시에 **'자동화 테스트'**와 **'GUI 테스트'**를 강제로 포함시키세요.
    - **프롬프트 필수 문구:** * "기능 구현 후, 정상 작동하는지 확인하는 **테스트 코드를 실행**하고 결과를 보고해줘."
        - "**Browser agent**를 사용해 실제 화면에서 버튼이 눌리는지 확인하고, 그 과정을 **영상으로 녹화**해서 보여줘."
    
    ### **4. 시각적 피드백 루프 (Visual Feedback)**
    
    Antigravity의 **Artifacts(아티팩트)**를 100% 활용하세요.
    
    - **핵심 전략:** 에이전트가 가져온 스크린샷이나 영상을 보고 '기획 의도'와 맞는지 확인합니다.
    - **수정 방법:** 코드를 수정하라고 하지 마세요. 화면에 대고 **"이 버튼 위치가 너무 왼쪽이야", "결제 완료 후 메시지 창이 안 떠"**라고 주석을 다는 것만으로도 충분합니다.

    # **1단계: 아이디에이션 & 컨텍스트 주입**
    
    비개발자 설계자에게 가장 중요한 첫 단추입니다. 코드를 한 줄도 모르는 우리가 에이전트에게 **"내가 원하는 것이 무엇인지"** 정확하게 인지시키는 과정입니다.
    
    ### **1. 에이전트에게 '눈'과 '뇌'를 만들어주기**
    
    에이전트는 똑똑하지만, 여러분의 머릿속을 볼 수는 없습니다. 단순히 "강의 사이트 만들어줘"라고 말하면 에이전트는 자신의 데이터만으로 '평균적인' 사이트를 만듭니다. 우리는 **컨텍스트(참고 자료)**를 주입하여 에이전트에게 시각적 기준과 비즈니스 로직을 제공해야 합니다.
    
    - **이미지(스크린샷) 제공:**
        - "이 사이트의 레이아웃이 마음에 들어"라며 이미지를 보여주세요.
    - **URL 링크 제공:**
        - 예: "인프런 사이트의 상세 페이지처럼 만들어줘"라고 주소를 주세요.
    - **문서 첨부:**
        - 기획안 메모나 워드 파일을 던져주세요.
    
    ### **2. 비개발자를 위한 '만능 요구사항' 공식**
    
    프롬프트를 어떻게 써야 할지 막막하다면 아래의 **[바이브-기획자 공식]**을 복사해서 사용하세요.
    
    ```markdown
    나는 **[어떤 서비스]**를 만들고 싶어.
    
    1. **참고 자료**
    내가 첨부한 **[스크린샷/URL]**을 확인해줘.
    (선택) 특히 **[특정 부분]**의 느낌이 살았으면 좋겠어.
    
    2. **핵심 기능 리스트
    - 기능1**
    **- 기능2**
    
    3. **제한 사항
    기술적**으로는 **[Python/Django]**를 사용할 거야.
    
    **4. 할 일**
    바로 코드를 짜지 말고, 네가 이해한 내용을 바탕으로 **구현 계획(Plan)**을 먼저 세워서 나에게 보여줘.
    ```
    
    ### **3. Antigravity의 차별점: 시각적 컨텍스트 인지**
    
    Antigravity의 에이전트는 단순한 텍스트 분석기가 아닙니다. **Browser Subagent**를 통해 여러분이 준 URL에 직접 접속하여 구조를 뜯어보고, 이미지를 분석하여 디자인 요소를 추출합니다.
    
    - **작업 포인트:** 에이전트가 "계획을 세웠습니다"라고 답변했을 때, 여러분이 준 참고 자료가 계획에 반영되었는지 확인하세요. 만약 반영되지 않았다면 "아까 준 URL의 메뉴 스타일이 빠졌어. 다시 반영해줘"라고 단호하게 말해야 합니다.
    
    ### **4. 이 단계의 핵심 요약**
    
    - **비개발자의 무기:** 코딩 실력이 아니라 **'좋은 레퍼런스를 찾아내는 안목'**입니다.
    - **주의사항:** 에이전트가 곧바로 코딩을 시작하게 두지 마세요. 반드시 **"계획(Plan)부터 세워줘"**라고 브레이크를 걸어야 합니다.

- 실리콘밸리 엔지니어와 함께하는 Docker
    
    **docker compose**
    
    여러 개의 컨테이너를 한 방에 띄우고 관리해 주는 **오케스트라 지휘자.**
    `docker-compose.yml`이라는 파일에 "웹 서버랑 DB 컨테이너를 같이 묶어서 띄워줘!"라고 선언해두면, 명령어 단 한 줄(`docker-compose up`)로 복잡한 다중 컨테이너 환경을 한 번에 실행시킬 수 있습니다.
    
    **docker engine**
    
    - **CLI (Command Line Interface):** 우리가 터미널(PowerShell, Git Bash 등)에서 `docker run`, `docker build` 같은 명령어를 치는 화면입니다. 사용자와 맞닿아 있는 껍데기(클라이언트)입니다.
    - **REST API:** CLI에서 친 명령어를 서버(데몬)가 알아들을 수 있게 전달해 주는 다리 역할을 합니다.
    - **Server (Docker Daemon - `dockerd`):** 뒤에서 묵묵히 일하는 진짜 일꾼입니다. API를 통해 명령을 받으면 실제로 이미지를 다운받고, 컨테이너를 만들고, 네트워크를 연결하는 등의 모든 실무를 담당합니다.
    
    **dockerfile**
    
    docker 이미지를 어떻게 만들지 결정하는 스크립트. 설계서임. "어떤 OS를 베이스로 할 건지", "어떤 파일을 복사해 넣을 건지", "실행할 때 무슨 명령어를 칠 건지"를 순서대로 쭉 적어둔 단순한 텍스트 파일입니다. 이 설계서를 도커 엔진에게 주면 그대로 이미지를 구워냅니다.
    
    **docker images**
    
    dockerfile을 통해 만들어진 **읽기 전용** 템플릿. 한 번 만들어진 이미지는 절대 변하지 않습니다(불변성).
    
    **docker containers**
    
    읽기 전용인 이미지를 메모리에 올려서 **실제로 실행시킨 상태**.
    
    **docker hub**
    
    docker image를 공유할 수 있는 클라우드

    # **docker 실습**

    ## 1. Docker Image를 만드는 방법 (도커파일 작성 & 빌드)
    
    내가 짠 애플리케이션 코드를 도커 환경에서 실행할 수 있도록 '붕어빵 틀(이미지)'로 굽는 과정입니다.
    
    **① `Dockerfile` 작성**
    
    프로젝트 최상단 폴더에 `Dockerfile`이라는 이름의 파일을 만들고 레시피를 적습니다. (예: Spring Boot 서버)
    
    ```markdown
    # 1. 자바 17 환경을 가져옴 (베이스 이미지)
    FROM eclipse-temurin:17-jdk-alpine
    
    # 2. 내 컴퓨터의 빌드된 jar 파일을 컨테이너 안으로 복사
    COPY target/my-app.jar /app.jar
    
    # 3. 컨테이너가 켜질 때 실행할 명령어
    ENTRYPOINT ["java", "-jar", "/app.jar"]
    ```
    
    **② 터미널에서 이미지 빌드 (굽기)**
    
    ```markdown
    docker build -t my-spring-app .
    ```
    
    - `t my-spring-app`: 만들어질 이미지에 'my-spring-app'이라는 이름표(태그)를 붙입니다.
    - `.`: "현재 폴더에 있는 Dockerfile을 사용해라"라는 필수 기호입니다.

    ## 2. Docker Volume을 만드는 방법 (데이터 영구 저장)
    
    컨테이너는 지워지면 내부 데이터도 다 날아갑니다. MySQL 같은 DB를 띄울 때 데이터가 날아가지 않도록, 내 컴퓨터 하드디스크의 공간(볼륨)을 컨테이너와 '연결(마운트)'해주는 작업입니다.
    
    **① 볼륨 생성하기**
    
    ```markdown
    docker volume create db-data
    ```
    
    - `db-data`라는 이름의 안전한 보관함을 내 컴퓨터에 만듭니다.
    
    **② 컨테이너 실행 시 볼륨 연결하기 (`-v` 옵션)**
    
    ```markdown
    docker run -d -p 3306:3306 -v db-data:/var/lib/mysql -e MYSQL_ROOT_PASSWORD=1234 mysql:8.0
    ```
    
    - `v db-data:/var/lib/mysql`: 내 컴퓨터에 만든 `db-data` 볼륨을, 컨테이너 내부의 MySQL 데이터 저장 경로(`/var/lib/mysql`)와 연결(동기화)합니다.
    - 이제 DB 컨테이너를 삭제하고 다시 띄워도 데이터는 안전하게 남아있습니다.

    ## 3. Docker Compose를 사용하는 방법 (다중 컨테이너 한 방에 띄우기)
    
    실제 서비스는 "웹 서버 + DB"처럼 여러 개가 세트로 돌아갑니다. 이걸 한 번에 묶어서 실행하고 종료하는 오케스트레이션 방법입니다.
    
    **① `docker-compose.yml` 작성**
    
    프로젝트 폴더에 파일을 만들고, 같이 띄울 컨테이너들을 정의합니다.
    
    ```markdown
    version: '3.8'
    
    services:
      # 1. 데이터베이스 컨테이너
      db:
        image: mysql:8.0
        ports:
          - "3306:3306"
        environment:
          MYSQL_ROOT_PASSWORD: rootpassword
          MYSQL_DATABASE: mydatabase
        volumes:
          - db-data:/var/lib/mysql
    
      # 2. 백엔드 서버 컨테이너
      web:
        build: .  # 현재 폴더의 Dockerfile을 빌드해서 띄움
        ports:
          - "8080:8080"
        depends_on:
          - db      # db가 먼저 켜진 후에 web을 켜라
    
    # 사용할 볼륨 선언
    volumes:
      db-data:
    ```
    
    **② 터미널에서 컴포즈 실행 & 종료**
    
    - **모두 띄우기 (실행):**Bash
        
        ```markdown
        docker-compose up -d
        ```
        
        *(알아서 이미지를 빌드하고, 네트워크를 묶고, 백그라운드에서 실행시킵니다.)*
        
    - **모두 내리기 (종료 및 삭제):**Bash
        
        ```markdown
        docker-compose down
        ```
