# 청각 장애인을 위한 소통 서비스

### 한줄소개

<aside>

음성을 텍스트로 번역하는 것을 넘어, **감정과 의도까지 시각화하고 음성으로 재현하는 AI 기반 양방향 통화 서비스**

</aside>

### 상세설명

본 서비스는 청각장애인과 비청각장애인이 전화 통화를 보다 자연스럽고 감정 왜곡 없이 할 수 있도록 돕는 AI 소통 플랫폼이다.

일반 자막 서비스는 단순히 음성을 텍스트로 변환하는 데 그치지만, 실제 대화에서는 **억양·강도·감정**이 중요한 의미를 가진다. 청각장애인은 이러한 요소를 인지하기 어려워 오해가 발생할 수 있다.

본 서비스는 다음을 해결한다:

- 비청각장애인의 음성을 STT로 텍스트화
- 음성 및 텍스트 기반 감정 분석 수행
- 감정을 직관적으로 시각화 (형태·아이콘·강도 표시)
- 청각장애인이 입력한 텍스트를 본인 음성 톤으로 복제하여 TTS 송출
- 감정 오해를 줄이기 위한 AI 의도 설명 기능 제공

즉, 이 서비스는 단순 자막 전화가 아니라  **“감정을 번역하는 전화 서비스”**이다.

### MVP 기능

### 1. 청각장애인 → 비청각장애인

- 텍스트 입력
- 사전 녹음 기반 음성 톤 복제 TTS
- 감정 선택 기능 (기쁨/차분/단호)
- 선택 감정에 따른 TTS 톤 조절
    - 감정 버튼 3개(이모지+텍스트): `🙂 기쁨 / 😐 차분 / 😠 단호`

---

### 2. 비청각장애인 → 청각장애인

- 실시간 STT 변환
- 텍스트 출력
    
    **UI 예시**
    
    - 최근 발화는 크게(가독성↑)
    - 이전 발화는 접어서 히스토리로 남김
    - 스크롤 올리면 전체 대화 로그 확인 가능
- 감정 분석 (5단계 분류)
- 감정 아이콘 표시
    - **예시 UI**
        - 😠 `왜 연락 안 했어?`
        - 😟 `요즘 많이 힘들어 보여서 걱정돼.`
    - **포인트**
        - 이모지 + 짧은 라벨을 같이 붙이면 더 명확함
            - 😠 `강한 어조`
            - 😟 `걱정`
- 감정 강도 게이지 표시
    - **예시**
        - 😠 화남 (강도 80)
            
            `왜 그렇게 했어?`
            
        - 😠 화남 (강도 30)
            
            `좀 서운했어`
            
    - **UI 예시**
        - 작은 막대 게이지: `🔥 ███████░░ 70%`
    - **효과**
        - 청각장애인이 “진짜 화난 건지 / 약간 짜증인지”를 구분 가능
- 말풍선 형태 변화 (감정 기반)

---

### 3. 감정 오해 방지 AI

- 문장의 감정 + 숨겨진 의도 한 줄 설명
- 예:
    
    “왜 연락 안 했어?”
    
    → 걱정이 섞인 강한 어조입니다.
    

---

### 4. 감정 완화 모드

청각장애인은 텍스트만 보면 말의 **의도(걱정인지, 화인지, 농담인지)를** 정확히 파악하기 어렵다.

같은 문장이라도 억양에 따라 의미가 완전히 달라질 수 있다.

예:

“왜 연락 안 했어?”

- 화난 것일 수도 있고
- 걱정한 것일 수도 있고
- 장난일 수도 있다

👉 이 기능은 **감정 + 숨겨진 의도까지 해석하여 한 줄로 설명**해주는 AI 보조 기능이다.

- 강한 어조를 중립적으로 재표현
- 정서 보호 기능

---

### 5. 빠른 응답 버튼

- 자주 사용하는 감정 기반 문장 버튼 제공
- 버튼 클릭 시 자동 음성 송출

    - TTS 음성 복제 품질: MVP에서는 “음색 중심”으로 가고, 감정 톤은 3단계로 단순화

### 기술 스택

- **Frontend**
    - React Native (통화 UI / 자막 UI / 감정 시각화 컴포넌트)
    - WebRTC (브라우저 기반 오디오 통화)
    - WebSocket(STOMP 또는 Socket.IO) (실시간 STT/감정 결과 전달)
- **Backend**
    - Spring Boot (세션/유저/통화방 관리, AI 호출 Orchestration)
    - Redis (세션 상태, 실시간 메시지 캐싱, 통화방/유저 상태 관리)
    - MySQL (유저/통화 기록/설정 저장)
- **AI / Voice**
    - STT: Whisper API **또는** Azure Speech-to-Text
    - 감정 분석/의도 설명/완화 리라이팅: GPT API (텍스트 기반)
    - TTS(음색/톤): Azure Neural TTS (Voice Cloning 가능 옵션)
        - MVP: 음색 복제 + 3단계 톤(기쁨/차분/단호) 정도로 제한

### 유저플로우(실행 알고리즘)

### A. 통화 시작

1. 유저가 통화방 생성/입장
2. WebRTC 오디오 연결 수립
3. 양측 클라이언트가 실시간 메시지 채널(WebSocket) 구독

---

### B. 비청각장애인 → 청각장애인 (음성 → 자막/감정)

1. 비청각장애인이 말함(오디오 스트림)
2. 서버(또는 클라이언트)가 일정 단위(예: 1~2초/문장 종료 감지)로 STT 요청
3. STT 결과 텍스트 수신
4. 감정 분석 요청
    - 입력: STT 텍스트 (+ 선택적으로 이전 1~2문장 컨텍스트)
    - 출력: 감정 라벨(5단계), 강도(0~100), 의도 한 줄(옵션)
5. 프론트 표시
    - 자막 출력(최근 발화 크게)
    - 😠/😟 등 감정 아이콘 + 라벨
    - 강도 게이지(🔥 70%)
    - 말풍선 형태 변화
    - (옵션 ON) 의도 한 줄 설명 표시

---

### C. 청각장애인 → 비청각장애인 (텍스트 → 본인 톤 음성)

1. 청각장애인이 텍스트 입력 또는 빠른 응답 버튼 선택
2. 감정 톤 선택(🙂/😐/😠)
3. TTS 생성 요청(음색=사용자 보이스 프로필, 톤=선택 감정)
4. 생성된 오디오를 비청각장애인에게 재생
    - 방식 1: 서버에서 오디오 URL 전달 → 상대 클라이언트가 재생
    - 방식 2: 서버가 RTP/WebRTC로 송출(난이도↑, MVP는 URL 재생 추천)

---

### D. 감정 완화 모드(옵션)

1. 청각장애인이 “완화 모드” ON
2. 상대 발화(STT 텍스트)가 들어오면
3. 리라이팅 요청: “중립/부드러운 표현으로 변환”
4. 표시 시 원문/완화문 중 택1 또는 병기
    - 예: 원문은 접고, 완화문을 기본 표시(토글로 원문 보기)
