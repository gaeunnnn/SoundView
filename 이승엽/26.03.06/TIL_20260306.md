# TIL - 2026.03.06

## 1. 환경 설정 및 의존성 이슈 해결
- **NumPy 2.0 충돌**: 최신 NumPy 설치 시 `AttributeError: _ARRAY_API not found` 에러 발생. TensorFlow 및 Librosa와의 호환성을 위해 `numpy<2` 버전으로 강제 다운그레이드하여 해결.
- **FastAPI/Pydantic**: `ImportError: cannot import name 'IncEx' from 'pydantic.main'` 발생. FastAPI 업데이트 과정에서 꼬인 Pydantic v1/v2 의존성을 최신 버전으로 정렬하여 조치.
- **가상환경 부재**: 시스템 Python 환경에서 작업 중 발생한 라이브러리 누락(`pandas`, `pytorch_lightning`, `omegaconf` 등)을 단계별로 파악하고 수동 설치하여 런타임 환경 구축.

## 2. AudioSep 모델 로드 및 소스 수정
- **PyTorch 보안 정책 대응**: 최신 버전에서 `torch.load` 시 `weights_only=True`가 기본값이 되어 발생하는 로드 실패 확인. `AudioSep/models/CLAP/open_clip/factory.py`에서 `weights_only=False` 및 `strict=False` 옵션을 추가하여 호환성 확보.
- **가중치 파일(weights) 유효성**: 자동 다운로드 시 리다이렉션 문제로 인한 0바이트 파일 생성 이슈 확인. 허깅페이스 공식 저장소(`lukewys/laion_clap`)를 통한 수동/자동 다운로드 경로 이원화 및 용량 검증 로직 추가.
- **함수 매핑 오류**: 리드미의 `inference` 함수가 실제 코드에는 `separate_audio`로 구현된 것을 확인하여 호출부 수정.

## 3. 오디오 처리 및 정밀 분석 알고리즘
- **구간 슬라이싱(Segment Slicing)**: 전체 오디오가 아닌, 사용자가 선택한 특정 시간대(start~end)만 물리적으로 잘라내어 AudioSep에 입력. 다른 구간의 잡음 유입을 원천 차단하고 분석 속도 향상.
- **시간 오차 보정**: YAMNet의 고정 프레임 간격(0.48s)과 실제 영상 길이의 차이로 발생하는 누적 오차를 해결하기 위해 `실제 길이 / 프레임 수` 기반의 가변 홉(Hop) 계산 로직 적용.
- **피크(Peak) 타임 탐지**: 구간 내에서 확률이 가장 높거나 진폭이 가장 큰 시점을 `peak_time`으로 정의. UI에서 클릭 시 해당 시점으로 즉시 이동하여 직관적인 검증 지원.
- **Padding 로직**: 구간 추출 시 앞뒤로 0.2초의 여유분을 주어 환경음의 시작과 끝이 급격하게 잘리는 현상 방지.

## 4. 분석 결과 정교화 및 노이즈 제어
- **노이즈 증폭 방지**: 분리된 소리의 진폭이 원본 대비 일정 수준(5%) 이하일 경우, 정규화 과정에서 소리가 비정상적으로 커지는 문제를 방지하기 위해 강제로 0% 처리하는 Threshold 로직 적용.
- **쿼리 보강(Prompt Engineering)**: 단일 단어(예: 'Speech')보다 서술형 문장(예: 'A clear human speaking voice')을 사용할 때 AudioSep의 분리 성능이 향상됨을 확인하고 매핑 로직 추가.
- **스테레오 병합**: 분리된 L/R(Mono) 파일을 서버에서 `np.vstack`으로 결합하여 2채널 스테레오 파일 생성. 최종 햅틱 밸런스를 한 번에 청음할 수 있는 환경 구축.

## 5. 모델 성능 관찰 및 고찰
- **YAMNet**: 521개 카테고리 내에서만 판단하므로 불꽃놀이를 '방귀'나 '스케이트보드'로 오진하는 등 복잡한 소리에서의 한계 명확히 확인.
- **CLAP**: 제로샷 분류 시 527개 전체 라벨을 CPU에서 연산할 때 발생하는 연산 부하 확인 및 텍스트 임베딩 캐싱(`text_embeds_527.pt`)을 통한 초기 구동 속도 최적화.
- **결론**: 청각장애인 햅틱 피드백을 위해서는 단순 분류(Classification)보다 물리적인 음원 분리(Source Separation) 결과의 RMS 데이터가 더 신뢰도 높은 기준이 됨을 데이터로 검증.
