# [기술 검토 보고서] 허밍 기반 실시간 악기 변환 기술의 구현 가능성 및 한계점

## 1. 프로젝트 개요

* **주제:** 사용자의 허밍(음성)을 실시간으로 분석하여 일렉기타 등 특정 악기 소리로 변환하는 서비스.
* **목적:** 악기를 다루지 못하는 사용자가 목소리만으로 작곡하거나 악기 연주를 시뮬레이션할 수 있는 기능 검증.

## 2. 사용 기술 스택 (Tech Stack)

* **Backend:** Python 3.11, FastAPI (Uvicorn)
* **Frontend:** JavaScript (Tone.js, RecordRTC)
* **AI/DSP Libraries:**
* `basic-pitch`: Spotify 개발 MIDI 추출 AI 모델.
* `librosa (pYIN)`: 주파수 추적 및 수학적 음정 분석.
* `parselmouth (Praat)`: 음성학 기반 정밀 음정 추론 엔진.



## 3. 단계별 구현 및 테스트 결과

| 단계 | 적용 방식 | 주요 이슈 | 결과 |
| --- | --- | --- | --- |
| **1단계** | AI 기반 MIDI 추출 (`basic-pitch`) | 의존성 라이브러리(Numpy 2.0) 충돌, 연산 부하 | **실패** |
| **2단계** | 주파수 추적 알고리즘 (`pYIN`) | 남성 저음역대 인식 오류 및 옥타브 불일치 | **보통** |
| **3단계** | 음성학 정밀 분석 (`Praat`) | 성대 떨림(Vibrato)으로 인한 노드 파편화 | **보통** |
| **4단계** | 오디오 직접 변조 (Direct Effector) | 악기 변환이 아닌 단순 음성 변조 느낌 강함 | **성공** |

## 4. 핵심 더미 코드 (Pitch-to-MIDI Logic)

AI 기반 분석이 아닌, 가장 정확도가 높았던 **Praat 엔진 기반의 음정 추출 코드** 샘플입니다.

```python
import parselmouth
import math

# 1. 오디오 파일 로드 및 주파수 추출
snd = parselmouth.Sound("input.wav")
pitch_track = snd.to_pitch()
pitch_values = pitch_track.selected_array['frequency']

raw_nodes = []
for i, freq in enumerate(pitch_values):
    if freq > 0: # 소리가 있는 구간만
        # 2. 주파수를 MIDI 번호로 변환 (수학적 보정)
        midi_pitch = round(69 + 12 * math.log2(freq / 440.0))
        
        # 3. 데이터 정규화 및 노드 생성
        raw_nodes.append({
            "time": pitch_track.xs()[i],
            "pitch": midi_pitch + 12 # 옥타브 보정
        })

# [핵심] 노드 병합 로직 (파편화 방지)
# 이전 노드와 음정이 같고 시간 간격이 0.05초 이내면 하나의 긴 음으로 합침

```

## 5. 프로젝트 실패 가능성 및 기술적 한계 (Risk Assessment)

본 프로젝트는 현재 수준에서 상용화 혹은 고퀄리티 서비스로 구현하기에 **실패 가능성이 매우 큼**을 확인했습니다.

### ① 목소리의 불안정성 (Vibrato & Jitter)

* 사람의 목소리는 악기처럼 고정된 주파수가 아니라 미세하게 계속 떨림.
* 컴퓨터는 이를 개별적인 수많은 음으로 인식하여 소리가 툭툭 끊기는 '파편화 현상'이 발생함.

### ② 배음(Harmonics) 인식 오류

* 콧소리나 낮은 목소리에서 발생하는 배음 때문에 실제 음보다 1~2옥타브 높은 엉뚱한 음이 찍히는 경우가 빈번함.

### ③ 환경 노이즈 및 마이크 성능

* 주변 소음이나 마이크의 노이즈 캔슬링 기능이 주파수 파형을 왜곡하여 AI의 분석 정확도를 급격히 떨어뜨림.

### ④ 실시간성 부족

* AI 분석 엔진(Python)과 사운드 합성 엔진(JS) 간의 통신 및 연산 시간으로 인해 실시간 연주 수준의 속도 구현이 어려움.

## 6. 종합 결론

단순한 형태의 이벤트를 위한 프로토타입 구현은 가능하나, **사용자의 의도대로 완벽하게 연주되는 악기 변환 서비스 구현은 현재 오픈소스 수준에서는 기술적 한계가 명확함.** 팀 차원에서 프로젝트를 진행할 경우, 단순 변환보다는 **감정 기반 음성 합성(Emotional TTS)** 등 다른 기술적 대안을 병행 검토할 것을 권장함.
