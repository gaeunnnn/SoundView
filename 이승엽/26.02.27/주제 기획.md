

# 📝 TIL (2026. 02. 27) : AI 기반 다이나믹 자막 플랫폼 기획 및 아키텍처 설계

## 🎯 1. 프로젝트 개요 및 기획 배경

**청각장애인 및 소리를 켤 수 없는 사용자를 위한 AI 기반 다이나믹 자막 생성 영상 플랫폼**

* **문제 제기:** 기존 영상 콘텐츠는 대사 중심의 STT(단순 텍스트 변환)에 그쳐, 환경음이나 화자의 감정/어조 등 '비언어적 청각 맥락'이 유실됨.
* **해결 방안:** AI 파이프라인(음성 인식, 환경음 탐지, 감정 분석)을 통해 청각적 디테일을 시각화(이모지, 폰트 애니메이션 등)하는 참여형 생태계 구축.
* **차별점 (핵심 기능):**
* **다이나믹 자막 자동 생성:** 대사 + 환경음 + 감정/사투리/소리 크기 시각화
* **AI 보이스 복제(RVC) 더빙:** 발음이 부정확한 청각장애인 크리에이터를 위해, 본인 목소리 톤을 학습시킨 고품질 AI 더빙 제공.

## 🛠️ 2. 핵심 기술적 병목(Bottleneck) 및 해결 아키텍처 설계

단순한 API 호출을 넘어, 6인 팀이 각 파트(FE, BE, AI)에서 마주칠 기술적 난관과 돌파구를 설계함.

### ⚙️ Backend (Spring Boot) & 인프라

* **[문제] 무거운 영상 처리로 인한 서버 다운 및 통신 타임아웃**
* **[해결 1] 오디오 추출 (FFmpeg):** 메인 백엔드에서 영상 전체를 AI 서버로 넘기지 않고, FFmpeg로 가벼운 오디오 파일(.wav)만 추출하여 전송. 네트워크 비용 최적화.
* **[해결 2] 비동기 메시지 큐 (RabbitMQ/Kafka):** AI 분석(수 분 소요)을 동기 처리하면 타임아웃 발생. 백엔드는 분석 요청만 큐에 던지고, 분석 완료 시 웹훅/SSE로 프론트에 알림을 주는 비동기 아키텍처 구성.

### 🤖 AI 파이프라인 (Python / FastAPI)

* **[문제] 통짜 오디오 파일 분석 시 발생하는 정확도 하락 및 메모리 에러**
* **[해결] VAD 기반 모듈화 파이프라인:**
1. **VAD (Silero):** 오디오 파형을 분석해 '사람 목소리 구간'과 '환경음 구간'의 타임스탬프를 1차적으로 분리 (자르기).
2. **STT (Faster-Whisper):** 잘라낸 목소리 구간에서 대사와 사투리 텍스트 추출.
3. **SER (Wav2Vec 2.0 파인튜닝):** 목소리의 높낮이/크기를 분석해 감정(기쁨/슬픔 등) 도출.
4. **SED (YAMNet):** 사람 목소리가 없는 구간을 분석해 환경음(장작 소리 등) 태그 추출.



### 🗄️ Database

* **[문제] 통짜 자막 파일(.srt) 저장 시 검색 및 수정 불가**
* **[해결] 자막 블록(Block) 단위 RDB 정규화:** 자막을 파일이 아닌 RDB의 Row 단위(`video_id`, `시작시간`, `종료시간`, `텍스트`, `감정`, `타입`)로 쪼개어 저장. 오타 부분 수정 및 해시태그 기반 특정 소리(예: #장작소리) 영상 검색 쿼리 최적화.

### 🖥️ Frontend

* **[문제] 무거운 영상 업로드 및 자막-영상 동기화 로직의 복잡성**
* **[해결 1] Chunked Upload:** 대용량 영상을 잘게 쪼개어 업로드하는 멀티파트 업로드 구현.
* **[해결 2] 상태 동기화 UI:** HTML5 `<video>`의 `currentTime` 이벤트를 0.1초 단위로 리스닝하여, 현재 재생 시간에 맞는 자막 블록과 다이나믹 애니메이션을 화면에 렌더링.

## 💸 3. 가성비 & 고효율 AI 모델 배포 전략

사비 출혈을 막고 평가위원에게 DevOps/FinOps 역량을 어필하기 위한 전략.

* **RunPod Serverless (Scale-to-Zero) 도입:** GPU 서버를 24시간 켜두지 않고, 요청이 들어올 때만 GPU가 켜져 과금되도록 설계하여 비용을 극단적으로 절감.
* **모델 최적화 (다이어트):** VRAM을 절반만 차지하고 속도는 4배 빠른 `Faster-Whisper` 사용 및 무거운 모델의 ONNX 변환 적용.
* **역할 분할 (Task Splitting):** 무거운 추론(STT, SER, RVC)만 GPU 런팟에 올리고, 비교적 가벼운 환경음 분석(SED)은 일반 CPU 서버로 분리.
