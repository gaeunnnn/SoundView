    # 프로젝트 개요
    
    ## 📌 프로젝트명
    
    ### **Draw & Tell – 아이 그림이 살아 움직이는 AI 애니메이션 동화**
    
    ---
    
    ## 1️⃣ 프로젝트 배경
    
    아이들은 그림을 통해 자신의 상상력과 감정을 표현합니다.
    
    하지만 그 그림은 대부분 사진으로 남거나 종이에 머무릅니다.
    
    또한, 부모가 매번 즉흥적으로 이야기를 만들어주는 것은 쉽지 않습니다.
    
    기존 AI 동화 서비스는 텍스트 기반이거나,
    
    정적인 이미지 중심으로 구성되어 있어
    
    아이의 “직접적인 창작물”을 적극적으로 반영하지 못합니다.
    
    ---
    
    ## 2️⃣ 프로젝트 목표
    
    > 아이가 그린 그림을 기반으로
    > 
    > 
    > AI가 동화를 생성하고,
    > 
    > 해당 그림이 실제 애니메이션 장면에 등장하며,
    > 
    > 부모의 목소리로 읽어주는 몰입형 오디오 동화 경험 제공
    > 
    
    ---
    
    ## 3️⃣ 핵심 가치
    
    ### 🎨 1. 아이 주도 창작
    
    아이의 그림과 말이 스토리의 중심이 됩니다.
    
    ### 🎬 2. 시각적 몰입
    
    아이 그림이 실제 장면 속 캐릭터로 등장하고 움직입니다.
    
    ### 🎤 3. 감성적 연결
    
    부모의 목소리로 읽어주는 맞춤 동화 경험을 제공합니다.
    
    ### 🤖 4. 멀티모달 AI 통합
    
    이미지 + 음성 + 텍스트 + 애니메이션을 결합한 통합 AI 파이프라인을 구현합니다.
    
    ---
    
    ## 4️⃣ 서비스 흐름
    
    1. 아이 그림 업로드
    2. 아이가 그림 설명 녹음
    3. STT 변환
    4. LLM이 3장면 구조 동화 생성
    5. 배경 이미지 생성
    6. 아이 그림 캐릭터화(배경 제거)
    7. 장면별 애니메이션 적용
    8. 등장 시 효과음(예: 공룡 울음소리) 재생
    9. 부모 목소리 TTS 낭독
    10. 완성된 동화 저장

    ## 5️⃣ 차별화 포인트

    # 🎬 장면 구성 구조
    
    동화는 항상 3장면 구조로 만듭니다.
    
    | 장면 | 내용 | 애니메이션 |
    | --- | --- | --- |
    | 1 | 도입 | 천천히 등장 |
    | 2 | 갈등/모험 | 이동/확대 |
    | 3 | 결말 | 안정/안기 |
    
    LLM은 반드시 다음과 같이 출력:
    
    ```
    {
      "title":"...",
      "scenes": [
        { "text":"...", "action":"walk" },
        { "text":"...", "action":"search" },
        { "text":"...", "action":"hug" }
      ]
    }
    ```
    
    ---
    
    # 🎨 애니메이션 방식 (6주 기준 현실적 설계)
    
    ## ✔ 기본 동작 템플릿 6개만 제작
    
    - walk → 좌우 이동
    - jump → 위로 이동
    - shake → 흔들림
    - zoom → 확대
    - fly → 위쪽 이동
    - hug → 두 객체 접근
    
    LLM은 action 태그만 반환
    
    프론트는 해당 템플릿 실행
    
    ---
    
    # 🎵 효과음
    
    - walk → 발소리
    - jump → 퐁 효과음
    - hug → 반짝 효과음
    - scene 전환 → 페이지 넘김 소리

    # 🎙 부모 목소리

    ## 권장 페이지 수와 재생 길이
    
    ### 타겟 6~7세 기준 권장
    
    - **6~8페이지** 권장
    - **페이지당 2~3문장**
    - 총 **15~24문장**
    - 낭독(아이에게 읽어주는 속도) 기준 **약 3~5분**
    
    ### 더 길게 하고 싶다면
    
    - **9~10페이지**까지 가능
    - 페이지당 2~3문장 유지 시 **약 5~7분**
    - (6~7세 기준으로는 6~8페이지가 가장 안전하고, 9~10은 “길게 읽는 아이”에 맞춤)
    
    ---
    
    ## “비동기 생성(읽는 동안 다음 페이지 만들기)”일 때 예상 시간
    
    ### 첫 재생 시작까지(사용자 체감 대기)
    
    - 이미지 분석 + 전체 구조(JSON) 생성 + **1페이지 TTS 생성**까지
    - 목표/현실 범위: **약 6~12초**
        - 빠르면 6~8초
        - 보통 8~12초
    
    즉, **첫 페이지가 재생되는 동안** 다음 페이지를 만들 수 있게 됩니다.
    
    ---
    
    ## 페이지별 생성 시간(재생 중 백그라운드)
    
    (페이지당 2~3문장 기준, TTS를 페이지 단위로 만드는 경우)
    
    - **페이지 1 TTS**: 1~3초 (재생 시작용)
    - **페이지 2~8 TTS**: 페이지당 **1~3초** 정도로 잡으면 됩니다.
    
    페이지 1 재생 시간은 보통 **20~35초** 정도이므로,
    
    그 시간 동안 **다음 페이지 5~20초 안에 충분히 준비**됩니다.
    
    → 결과적으로 **2페이지 이후부터는 끊김이 거의 없게** 만들 수 있습니다.
    
    ---
    
    ## 전체가 “완전히 다 준비”되는 시간(백그라운드 완료 시점)
    
    - 6~8페이지 기준:
        - 페이지당 1~3초 × (나머지 5~7페이지) = **약 5~21초**
    - 즉, **재생 시작 후 10~30초 내**에 전체 오디오가 대부분 준비되는 그림이 일반적입니다.
    
    (단, API 성능/병렬 처리/서버 상태에 따라 변동)
    
    ---
    
    ## 정리
    
    - **권장 페이지 수**: 6~8페이지
    - **권장 재생 길이**: 3~5분
    - **첫 페이지 재생 시작까지**: 6~12초
    - **다음 페이지 생성 시간(재생 중)**: 페이지당 1~3초
    - **전체 페이지 오디오 준비 완료(재생 시작 후)**: 대략 10~30초 내
